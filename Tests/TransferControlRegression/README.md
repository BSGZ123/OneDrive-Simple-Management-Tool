# 传输限速、优先级与剩余时间

任务中心的普通上传和下载均支持单文件及文件夹任务。在任务卡片展开“传输设置”：

- 限速单位为 KiB/s，0 表示不限速，默认为 0。输入后按 Enter 或离开输入框应用。文件夹内所有并发文件共享该任务的字节预算，其他任务有各自的预算；这是每任务上限，不是全应用总带宽上限。
- 优先级为低、普通、高，默认普通。上传和下载共用三个文件传输名额；优先级影响下一批等待文件，不中断已开始的文件。同级按入队顺序，等待每满 30 秒提升一级调度权重，避免低优先级持续饥饿。同步上传继续共享名额，使用普通优先级，保留原有同步页面。
- 限速和优先级随任务记录加密保存，恢复后继续生效；旧任务记录默认为普通、不限速。修改限速会让正在等待的读写及时使用新上限，暂停、取消和退出可以打断限速等待。
- 上传和下载均显示近 5 秒实际文件字节的平均速度，每 500 ms 更新。已有续传字节、目录扫描和本地校验不计入速度。上传分片传输中也会显示进度，而持久化偏移仍只采用云端确认值。
- 剩余时间由待传字节和近期速度估算，不包含扫描、最后的校验和服务端确认。样本不足、停滞、排队、暂停、中断、失败或目录大小不确定时显示“—”；完成显示 `00:00`。网络缓存和调度可造成短时波动，限速约束的是文件负载字节，不包含协议头开销。
- 限速主动等待与网络无响应超时分别计时，低速任务不会因为一次分片超过 60 秒而被错误取消。

## 自动化测试

```powershell
dotnet run --project Tests/TransferControlRegression/TransferControlRegression.csproj
dotnet run --project Tests/UploadRegression/UploadRegression.csproj
dotnet run --project Tests/DownloadRegression/DownloadRegression.csproj
```

`TransferControlRegression` 使用本机 HTTP 服务器和临时测试目录，不登录或访问真实 OneDrive。测试包含优先级次序、运行时调整、FIFO/防饥饿、排队取消与名额释放、并发共享预算、动态解除限速、近期速度和 ETA、旧记录兼容、上传/下载设置跨进程恢复、实际流限速、暂停恢复以及 65 KiB 文件以 1 KiB/s 上传超过 60 秒。最后一项有意耗时约 70 秒。

上传与下载回归额外检查生产文件夹执行路径是否将同一个预算传给所有子文件。`ResumeRegression` 继续覆盖真正的进程退出、上传服务端领先于本地、下载 Range 恢复、内容变化和会话失效。

## 上传暂停与批量控制

上传任务卡片及右键菜单提供暂停、继续和重试。暂停会取消正在等待的调度、限速或网络操作，并等待当前工作结束后显示“已暂停”。任务保留已创建的目录、已完成的文件和上传会话；继续时向服务端查询已接收范围，再从确认的位置传输。暂停后的百分比采用已确认字节，可能低于暂停前包含正在发送分片的实时百分比。服务端已确认完成的文件以完成结果为准。

上传、下载页各有四个批量按钮，只作用于当前页，点击时取任务快照：

- 全部暂停：暂停待开始及正在传输的任务；已经进入最终落盘的下载先完成落盘。
- 全部继续：恢复待开始、已暂停或重启中断的任务。
- 重试失败：重新执行失败任务的未完成项目，保留已完成文件；不主动启动暂停任务。
- 清理已完成：移除状态为“已完成”的记录，不删除本地或云端文件；失败、取消、跳过和未完成任务保留。某项记录移除失败时保留其卡片并显示保存错误，其他已完成任务仍能清理。

显式暂停状态跨重启保留，失败状态在退出后仍保留，便于重新打开时使用“重试失败”。退出确认期间批量命令禁用，取消退出后恢复。单任务限速、优先级及统一三个文件名额继续生效；暂停停止速度与 ETA 计时。同步上传页沿用自身控制。

`UploadRegression/PauseChecks.cs` 验证待开始/排队暂停、重复暂停、真实分片恢复、保留成功兄弟文件、暂停与移除竞争、冲突等待取消和退出状态。`DownloadRegression/BatchControlChecks.cs` 验证两个方向的批量任务筛选、命令状态通知、暂停记录保存、文件完整性、清理失败保留卡片、保留文件及退出期间的命令禁用。真实上传生命周期由 UploadRegression 覆盖，批量上传选择使用模拟任务边界。
