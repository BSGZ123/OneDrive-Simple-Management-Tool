# 文件夹同步回归

```powershell
dotnet run --project Tests/FolderSyncRegression/FolderSyncRegression.csproj
```

此项目直接编译生产同步引擎、配置存储、监测服务及 Graph 适配器。文件系统测试使用临时目录，Graph 元数据使用内存处理器，大文件分片仅发送到本机回环服务器；不会读取实际账号或访问 OneDrive。

覆盖首次递归同步（包括空文件和空目录）、内容指纹、相同大小和时间戳的修改、本地删除保留云端、重命名、云端变化不回传、文件占用、失败重试、取消、配置恢复和损坏、根目录名称、路径越界、监测与暂停恢复、重叠绑定、解除绑定、分页、空文件和分片上传、精确名称及上传结果校验、匿名分片和双语资源。

## 当前行为

- 左侧“文件夹同步”管理长期绑定；“任务 → 同步上传”展示当前处理的项目。
- 创建绑定时，两端根文件夹必须完全同名（包括大小写）；内部相对路径和名称也必须一致。
- 首次以本地内容上传整个目录，之后只上传新增或内容变化的项目；云端已有同路径同名文件被本地内容更新。
- 本地删除不发送云端删除请求。重命名或移动按新路径上传，旧云端副本保留。
- 应用运行期间监测，退出后停止；启动、恢复、手动检查和定期本地补扫会检查遗漏的变化。
- 同名文件/文件夹类型冲突、名称不一致、共享快捷方式、链接/目录联接、按需占位文件会显示问题，不自动重命名。
- 每个绑定串行处理，最多两个同步文件同时上传。文件打开期间拒绝写入；被占用的文件稍后重试。
- 正常补扫间隔五分钟，有错误时一分钟重试；事件合并约一秒。扫描使用内容摘要识别变化，不仅依赖修改时间。
- 配置保存在 `%LOCALAPPDATA%\OneDriveSimpleManagementTool\FolderSync`，按绑定分文件原子保存；大目录最多每两秒检查点一次，结束/暂停时保存。异常退出可能重复少量已完成上传，不会将失败项目记为成功。
- 后台只对绑定账号静默认证，不弹出登录窗口。登录失效时先到“文件”重新登录，再恢复绑定。
- 不提供托盘常驻或开机启动；暂停正在上传的文件后，恢复时该文件重新上传，不承诺跨进程续传上传分片。

真实账号、权限、配额和云端服务行为仍需使用可丢弃目录验收。不能把模拟测试通过视作实际云端验证。
